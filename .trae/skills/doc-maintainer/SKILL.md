# 项目文档维护 Skill

## 作用

每完成一次开发任务后，自动更新项目根目录下 `项目沉淀资料/` 文件夹中的两份文档：

- `项目沉淀资料/work_reports.md` —— 工作汇报总览，记录各阶段完成的功能、进度、问题与建议。
- `项目沉淀资料/technical_docs.md` —— 技术文档总览，记录架构设计、接口定义、踩坑指南与交接约定。

这两份文档的核心目的是：**让其他任务窗口的 AI 能够快速了解项目当前开发情况，避免上下文缺失造成的不良影响。**

## 文档路径（重要）

两份文档均位于项目根目录的 `项目沉淀资料/` 文件夹下：

- `/Users/bytedance/AndroidStudioProjects/MateFairy01/项目沉淀资料/work_reports.md`
- `/Users/bytedance/AndroidStudioProjects/MateFairy01/项目沉淀资料/technical_docs.md`

**读取和更新时务必使用上述完整路径，不要在项目根目录下查找。**

## 触发时机

在以下情况下必须调用本 Skill：

1. **完成一次开发任务后**（如实现新功能、修复 Bug、重构代码）。
2. **会话结束前**，确保本次会话的所有进展都被记录。
3. **用户明确要求更新文档**时。
4. **切换 Agent 或任务窗口前**，确保上下文可被下一个 Agent 继承。

## 更新规范

### work_reports.md 更新规则

在文档末尾追加新的阶段汇报，包含以下内容：

1. **阶段标题**：如 `## Phase X 工作汇报：xxx功能开发`
2. **功能开发完成情况**：
   - 新增/修改了哪些文件和类
   - 实现了什么功能，解决了什么问题
   - 关键设计决策（如算法选择、状态机设计等）
3. **编译与测试情况**：是否编译通过、测试是否通过
4. **技术债务与踩坑记录**：本次开发中遇到的关键问题及解决方案
5. **后续开发建议**：下一步可以做什么，有什么优化方向

### technical_docs.md 更新规则

在文档末尾追加新的技术交接章节，包含以下内容：

1. **阶段概述**：本阶段的核心交付物与技术改进点
2. **核心架构与类说明**：
   - 新增/修改的类及其职责
   - 关键字段和方法的说明
   - 逻辑流程（使用步骤编号）
3. **SDK/框架避坑指南**：本次开发中发现的新坑点及解决方案
4. **设计说明**：为什么这样设计（如状态机设计、算法选择等）
5. **资源文件说明**：新增或修改的资源文件路径

## 注意事项

1. **不要删除旧内容**：两份文档都是累积式的，新内容追加在末尾。
2. **保持格式一致**：使用与现有文档相同的 Markdown 格式和层级结构。
3. **更新文档头部的时间戳**：将 `最后更新：` 改为当前日期。
4. **代码片段要完整**：技术文档中的代码示例必须是可运行的完整片段。
5. **路径使用绝对路径**：如 `/Users/bytedance/AndroidStudioProjects/MateFairy01/...`
6. **中文撰写**：文档内容使用中文，保持与现有文档一致。

## 执行步骤

1. 读取现有的 `项目沉淀资料/work_reports.md` 和 `项目沉淀资料/technical_docs.md`（使用完整路径）
2. 根据本次开发任务的内容，撰写新的汇报章节
3. 更新两份文档（追加内容 + 更新头部时间戳）
4. 确认文档保存成功
