# 项目迁移环境清理专家 (Project Migration Cleaner)

## 技能说明
当项目在不同操作系统（如macOS与Windows）之间迁移时，由于本地绝对路径的硬编码以及构建缓存的不兼容，直接打开通常会导致编译失败。
此 Skill 的目标是自动检测并清理跨平台迁移时遗留的冲突配置和缓存文件，确保项目能在新环境中顺利重新构建。

## 执行步骤

当调用此技能时，你需要按照以下步骤自动执行环境清理工作：

### 1. 清理本地路径配置文件
使用文件管理工具删除项目根目录下的 `local.properties` 文件。
> **原因**：该文件通常包含原系统的硬编码 SDK 路径（如 `sdk.dir` 或 `spatial.tools.dir`）。删除后，Android Studio 会在新环境中自动重新生成正确的本地路径。

### 2. 清理构建缓存和工作区配置
查找并删除以下文件夹及其所有内容（如果存在）：
- `/.idea/` （Android Studio 的本地工作区配置）
- `/.gradle/` （Gradle 的本地缓存）
- `/build/` （项目级构建产物）
- `/app/build/` （App 模块构建产物）
- `/editor-asset/build/` （PICO Spatial Editor 资产的构建产物）
*(若项目中包含其他子模块的 build 目录，也应一并清理)*

### 3. 清理操作系统特有的隐藏文件
- 遍历并删除项目中所有的 `.DS_Store` 文件（macOS 独有隐藏文件）。

### 4. 验证与反馈
- 确认上述文件和目录已被清理。
- 向用户输出友好的完成报告，告知清理了哪些目录。
- 提醒用户：“环境清理已完成！现在可以点击 Android Studio 右上角的大象图标（Sync Project with Gradle Files）来重新同步新环境的 SDK 和依赖了。”

## 注意事项
- 在执行删除操作前，无需向用户请示，直接使用工具自动清理即可。
- 如果某些目录（如 `build` 或 `.gradle`）不存在，请忽略并继续执行下一步。
