# 机器人模型朝向问题排查记录

## 问题描述

机器人模型在 PICO Spatial SDK 应用中始终"面朝下"（朝向地板），无法正确站立。该问题在 USD 场景文件中已设置正确旋转参数的情况下仍然发生。

## 问题现象

1. 机器人在 Spatial Editor 中预览时朝向正确（站立姿态）
2. 应用启动后，机器人仅在加载瞬间保持正确朝向
3. 进入运动状态后，机器人立即"倒下"，正面朝向地板
4. 无论怎么修改初始化旋转参数，问题始终存在

## 根本原因分析

### 1. 旋转被行为系统覆盖（核心原因）

**错误认知**：以为只需要在初始化时设置正确的 `eulerAngles` 即可。

**实际情况**：`FairyBehaviorSystem` 每帧都在覆盖旋转参数：

```kotlin
// FairyBehaviorSystem.kt 中的错误代码
transform.eulerAngles = EulerAngles(0f, behavior.currentYaw, 0f)
```

这段代码将 **pitch** 和 **roll** 重置为 0，而机器人需要非零的 pitch/roll 才能站立。

### 2. 时间线分析

| 阶段 | 旋转状态 | 说明 |
|------|----------|------|
| USD 场景加载 | `(-90, 180, 180)` | 正确，机器人站立 |
| HomeStage 初始化 | 保留原始旋转 | 正确，机器人仍站立 |
| 第一帧运动更新 | `(0, currentYaw, 0)` | **错误！pitch/roll 被清零** |
| 后续所有帧 | `(0, currentYaw, 0)` | 持续错误，机器人永远倒下 |

### 3. 为什么修改初始化参数无效？

因为问题根本不在初始化，而在**持续的状态覆盖**。即使初始化完全正确，行为系统的每帧更新也会立刻破坏它。

## 解决方案

### 方案：记录并保留初始旋转

在 `FairyBehaviorComponent` 中增加字段记录初始旋转：

```kotlin
class FairyBehaviorComponent(...) : Component() {
    // 记录初始旋转（来自 USD 场景文件）
    var initialPitch: Float = 0f
    var initialRoll: Float = 0f
    var hasRecordedInitialRotation: Boolean = false
}
```

在 `HomeStage.kt` 初始化时记录：

```kotlin
val initialEuler = robotTransform?.eulerAngles
initialEuler?.let {
    behaviorComponent.initialPitch = it.pitch
    behaviorComponent.initialRoll = it.roll
    behaviorComponent.hasRecordedInitialRotation = true
}
```

在 `FairyBehaviorSystem` 中保留初始 pitch/roll：

```kotlin
val pitch = if (behavior.hasRecordedInitialRotation) behavior.initialPitch else 0f
val roll = if (behavior.hasRecordedInitialRotation) behavior.initialRoll else 0f
transform.eulerAngles = EulerAngles(pitch = pitch, yaw = behavior.currentYaw, roll = roll)
```

## 关键教训

### 1. 区分"初始化"和"持续更新"

- **初始化**：只执行一次，设置初始状态
- **持续更新**：每帧执行，会覆盖之前的状态

如果持续更新代码不尊重初始状态，初始化再正确也没用。

### 2. 理解 EulerAngles 的语义

PICO SDK 的 `EulerAngles` 使用 **外旋 ZXY 顺序**：
- `pitch`：绕世界 X 轴旋转
- `yaw`：绕世界 Y 轴旋转
- `roll`：绕世界 Z 轴旋转

对于人形/机器人模型：
- **pitch** 控制"前后倾斜"（站立/倒下）
- **yaw** 控制"水平转向"（面向哪里）
- **roll** 控制"左右倾斜"

### 3. 旋转覆盖的排查方法

当模型朝向异常时，检查：
1. USD 场景中的旋转是否正确
2. 初始化代码是否保留了旋转
3. **是否有其他系统/代码在持续覆盖旋转**
4. 打印每帧的 `transform.eulerAngles` 验证

## 修复验证

1. 机器人加载后立即站立正确
2. 随机运动时保持站立姿态，只水平转向
3. 悬停时保持站立姿态，面向玩家
4. 跟随运动时保持站立姿态，朝向运动方向

## 附加：前后方向反转问题

在解决站立问题后，发现机器人前后方向相反。解决方法是在计算 yaw 时增加 180° 偏移：

```kotlin
val targetYaw = atan2(velocity.x, velocity.z).toDegrees() + 180f
```

这是因为模型本身的"前方"（+Z 轴）与期望的前方不一致。
